## Подробный план этапов разработки NotMice

Проверил документы в `TZ_MVP_28_DAYS.md`, `TECHNICAL_ARCHITECTURE.md`, `STRATEGIC_PROPOSALS.md` и `UI_UX_DESIGN_SYSTEM.md`. Основной ориентир — реализовать MVP за 28 дней: загрузка анализов, распознавание, проверка пользователем, расчёт PhenoAge и публичный export.

---

## 1. Цель и ограничения MVP

### Цель
Сделать рабочий сквозной сценарий:
1. пользователь регистрируется,
2. загружает PDF/скан анализов,
3. система извлекает биомаркеры,
4. человек подтверждает или правит данные,
5. рассчитывается PhenoAge,
6. данные становятся публично доступными при включённом тумблере.

### Не входит в MVP
- мобильные приложения,
- Telegram-бот,
- хранение оригиналов документов,
- токеномика/крипто,
- медицинские диагнозы и назначения.

---

## 2. Архитектурный фокус

Согласно `TECHNICAL_ARCHITECTURE.md`, проект должен строиться по чистой архитектуре:

- Backend: FastAPI + SQLAlchemy Async + PostgreSQL
- Frontend: Astro + Tailwind + минимальный TypeScript
- OCR/LLM: pdfplumber + Claude Vision API
- DevOps: Docker, Docker Compose, GitHub Actions
- Quality: ruff, mypy, pytest, Alembic

Главная идея: в памяти обрабатывать документ, вычислять хеш, извлекать показатели, после подтверждения удалить исходный файл из памяти.

## 6. Definition of Done для MVP

MVP считается готовым, если выполнены все пункты:

- пользователь проходит регистрацию по seed-фразе,
- может загрузить PDF или изображение,
- данные извлекаются и отображаются для проверки,
- человек подтверждает/редактирует значения,
- система расчитывает PhenoAge,
- данные могут быть опубликованы в публичный API,
- исходный документ не сохраняется на диске,
- вся запись содержит provenance,
- есть базовый веб-сайт и docs,
- набор проходит QA и smoke-tests.
